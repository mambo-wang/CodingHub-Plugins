# 文章结构模板（四段式）

以第 01 篇《Higress 是什么：能力全景、工作原理与实操》为定型样本。新篇目照此展开，只换内容不换骨架。

## 骨架总览

| 部分 | 做什么 | 占篇幅 |
|---|---|---|
| 标题 | `# AI 网关系列 NN｜<副标题>` | — |
| 导语 | blockquote 三段：系列说明 / 本篇定位 / 环境说明 | ~150 字 |
| 一、是什么 | 官方定义拆解 → 能力与效果 → 总纲图 → 亮出判断 | ~25% |
| 二、怎么工作 | 机制分组 → 原理图（≥1 张）→ 反直觉小节（核心论点落点） | ~35% |
| 三、实操 | Step 0..N 分步 + 坑 callout + 截图 + 验证 | ~30% |
| 四、小结与导读 | 底座回扣 / 本质一句 / 坑回顾 / 系列导读表 / 互动 | ~10% |
| 脚注 | 来源 + 核验说明 + 脱敏声明 | 1 段 |

## 标题与导语

- 标题：`# AI 网关系列 NN｜Higress 是什么：能力全景、工作原理与实操`。副标题用「主题：并列关键词」格式。
- 导语三要素（照抄句式，替换内容）：

```
> 《Higress AI 网关全解析》是一个 11 篇的系列，结构固定：先讲清这个能力是什么、能做什么，再拆开它在数据面是怎么实现的，最后动手跑一遍。
>
> 第 01 篇是总览：**Higress 是什么、它的能力边界在哪、Ingress + Istio + Envoy + WASM 这套组合是怎么拼起来的、以及从零把整条链路跑通一次**。后面十篇，一格一格地填。
>
> 环境统一是 Docker 版 Higress 独立部署，不是 K8s；文中的配置和命令都基于这套环境。
```

## 一、是什么

两种开篇任选：**官网定义开篇**（引一句话定义 → 拆开逐段解读 → 亮出「AI 原生」的分量）或**能力开篇**（直接讲这个能力解决什么）。段落节奏：短段 + 每段一个 bold 首句。

必备元素：

1. **官方定义拆解**（引官网原句，概括不搬运）。
2. **四条核心优势**（若该主题有官方归纳）：每条一小段，指明哪条信息量最大并「展开说」。
3. **总纲图**：系列坐标系（01 是能力地图，04/05 篇在它上面标注新增插件即可，读者建立连续心智）。
4. **亮判断**：「最被低估的是……最被高估的是……」这类立场句，并说理由（讲清判断标准，不是抛观点）。

## 二、怎么工作

- 开头先给**全局分组**（bullet：谁管什么、各一段话），再分小节展开。
- **至少一张原理图（硬要求）**：图型按内容选——分层 / 组件关系用**架构图**，一条数据路径用**流程图**，跨方向或跨时间的协作（请求下行 / 响应上行）用**时序图**；图贴着对应机制小节放，fig8 式时序图要配一句过渡说明「这张图在讲什么」。01 篇三张样板：图 2 分层架构、图 3 过滤器链（流程图）、图 4 一次调用时序图（**mermaid 源** `fig8-request-sequence.mmd`，改文案即可复用）；画法分工（架构/流程图用 HTML 骨架，时序图用 mermaid）与骨架复用见 `toolchain.md` 第 7、8 条。
- 小节两种视角：**控制面视角**（「你点控制台时发生的事」——动作串起链路）或**数据面视角**（「一条请求穿过……」——数据流串起链路）。
- 机制事实必须带出处：源码 `path:line`、`config_dump` 读数、Nacos 落库片段。这类引用直接放正文，脚注不再重复。
- **反直觉小节**是本段高点：如 01 的「AI 网关和 API 网关的分界线」（传统网关三条假设逐条击碎）。新篇目的核心论点就落在这里，格式为「三个假设 / 三个误解 / 两个词要分清」这类可数的结构。
- 需要对比时用表格：两列语义（如入站/出站凭据）、参数表（phase/priority）。表格信息密度高，一个足够。

## 三、实操

- 开头两句：命令可直接抄 + 入口地址（控制台 `:8080`，网关 `:80`）+ 与原理图对照看（「前四步在往链上装东西，第五步才给链子上门锁」这类总述）。
- 步骤格式：`**Step N · 动作**` 单行加粗标题，正文 = 动作描述 + yaml/bash 片段 + 落库形态（注释写路径）+ 截图。
- **坑写成 callout**（blockquote，就放在咬人的那一步）：
  - 普通坑：一两句，直接给规避动作（「`global_auth` 默认是 `false`，别顺手改成 `true`」）。
  - 危险步骤：标注「**这里是全文最危险的一步**」，讲清爆炸半径和正确顺序。
- 每步给「落库后长什么样」（`mcpbridges/…`、`wasmplugins/…`、`ingresses/…` 带注释的 yaml 片段）。
- **贴出来的配置要逐键交代清楚**（铁律 9）：这一格控制什么、不写时插件取什么缺省值、写错或漏写是什么后果。三类事实必须回源码核实而不是抄文档——缺省分支（`if x == 0 { x = 默认 }`）、会让整份配置加载失败的校验（`return fmt.Errorf(...)`，写错不是「没生效」而是「插件起不来」）、只在另一个键打开时才被读的键（成对配置要说明耦合）。**最优先查的是「配了但运行时不读」**：表单逼你填的 `apiKey` 某些引擎根本不读；执行条件挂在别的键上时，单看这段 YAML 以为生效、实际一次调用都不发（`ai-search` 的 `type: arxiv` 只在 `EngineType == "arxiv"` 时执行，而这个值只由 `searchRewrite` 的返回值解析出来——不配 `searchRewrite`，arxiv 一次都不查）。写法用标识符名 + 缺省值 + 后果，不写行号（铁律 7）。
- **每步必须有一份「看得见效果」的证据**（截图或读数都行，二者都不是的算返工）：命令 + 期望输出成对出现，输出原样贴进代码块，别只写「这时你会看到……」。证据形状按内容挑一种：
  - **接口入参 / 返回值**：请求体 + 响应片段（`content`、`finish_reason`、`Content-Type`）。
  - **网关台账**：access log 的 `ai_log` 子对象（`model` / `input_token` / `output_token` / `cache_status` / `duration`）。
  - **数据面配置**：`config_dump` 里过滤器有没有挂上、route 落到哪个 cluster。
  - **旁证存储**：Redis `GET`/`TTL`、假服务的调用清单、网关日志里的 panic 回溯。
  - 断言「插件到底改了什么字节」时，日志和回答都反推不出来——搭**回声上游**：把这条路由的 provider `openaiCustomUrl` 临时指到一个不生成内容、只把自己收到的 Body 排版回吐的 OpenAI 兼容服务，跑完切回真服务商。让同一个假服务既当回声上游、又当插件配置里的检索/改写服务时，**靠 Host 分辨这次出网是谁发起的**（网关最终那次带端口，插件那几次是配置里的服务名），正文开头把 `host=`、`<absent>`、`N chars` 这些记号约定清楚。
  - 多个组件互相覆盖时，给**单变量对照组**（只换一格，读数并列贴），并把全开的终态收在最后一步当验收（重复的 message、真问题落在第几条、被拿去检索的字符串是不是原问题、哪个请求键被静默改掉）。
- 验证步放在最后：**别看控制台，看数据面**（`config_dump` 命令 + 期望输出），并给出习惯建议。
- 收尾：对象清单（这些点击最后变成了什么）+ 监控图（如有）+ 一个跨篇预告句（「为什么用量会出现小数，第 07 篇专门讲」）。

## 四、小结与系列导读

三段 + 表 + 互动：

1. **底座回扣**：核心技术底座三样，各自决定了什么性格。
2. **本质一句**（加粗）：「AI 网关的本质，是把『模型调用』从一次网络请求，变成一个有身份、有成本、有内容属性、可审计的业务事件。」
3. **坑回顾**：一句话列出全部坑名，说它们散布在哪些步骤。
4. **系列导读表**：11 行（序号 | 主题 | 核心问题），本篇行加粗并标「（本篇）」。表随系列推进更新标题/核心问题列。
5. **互动句**：欢迎评论 + 抛一个开放问题（最好挑一个自己持保留态度的判断）。

## 脚注

单段 `*…*`，三件事齐全：来源（官网链接 + 源码分支核验 + 配置来源）、版本口径、脱敏声明。样本：

```
*Higress 的产品定位与核心优势引自官网 [Higress 是什么](https://higress.ai/docs/latest/overview/what-is-higress/) 与 [Wasm 生效原理](https://higress.ai/docs/latest/user/plugins/wasm-dev/wasm19/)；插件清单与 provider 数量核对了 v2.2.4 / main 两个分支的源码，过滤器链顺序来自 Envoy 的 `config_dump`。示例中的 API Key 已脱敏。*
```

## 图注与编号

- 原理图 alt：`图 N：标题`（N 是按全文出现顺序的展示号，与文件名无关）。
- 截图 alt：`控制台：动作` 或 `Grafana：面板名`。
- 图放正文里就近；截图紧跟对应 Step 的配置片段。
- 段间分隔：`## ` 大节之间用 `---`；小节之间不用。
