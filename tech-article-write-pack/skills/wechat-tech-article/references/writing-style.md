# 文风与禁则

## 人称与语气

- 用「你」直接称呼读者；「我」只出现在**判断句**里（「我认为最被低估的是第 03 类」「我对『网关层做 RAG』是持保留态度的」），不写「我试了一下」这类流水账。
- 承认不确定性：「这类差异本身不致命，致命的是数量级」「排查时别以为是上游挂了」。
- 开头可用设问引段：「想知道一个人是不是真的理解 AI 网关，问他这个问题就够了」——全篇不超过一处。
- 短句为主，长短交错；先结论后展开。段尾不要都收成感叹式总结。

## 数字与事实的呈现（铁律 1 的执行细则）

| 场景 | 错误写法 | 正确写法 |
|---|---|---|
| 插件版本 | 我拉下来一看是 2.0.1 | 网关镜像 2.2.4（当前最新 release）配套的插件还全是 2.0.1 |
| 分支对比 | 本机把两个分支都翻了一遍 | v2.2.4 和 main 分支完全一致 |
| 机制断言 | 我实测覆盖没有开关 | 翻遍 v2.2.4 和 main 两个分支：**这个覆盖没有开关** |
| 过滤器链 | 我在 config_dump 里看到顺序是 | 落库后的配置长这样（给表格）……顺序不是随手定的 |

- **正文不写源码行号**（用户明确要求，2026-10-14：「把内容中写的代码行号去掉」）。研究阶段照旧记 `path:line`，那份定位留在记忆和工作笔记里，发布稿里只说行为。出处这样给：版本锚（「v2.2.4 的源码里」「同一 tag 的响应侧」）、标识符名（`checkList`、`DontReadRequestBody()`、`config.defaultEnable = true` 这类原样引用的代码片段）、文件级线索（`http_wrapper.go`）、运行证据（`config_dump`、Nacos 落库文件、`ai_log` 读数）。文末引文写「插件行为核对了 v2.2.4 tag 源码」，别写「行号可直接对」。
- 禁词族：本机、实测（作叙事主语时）、我这台、跑得动、吃掉多少内存。写完后 grep 复查。

## 语言细节

- 简体中文；全角标点；中文与英文/数字/代码之间留一个空格。
- 引号用「」和『』；行内代码、字段名、插件名、命令一律反引号。
- 破折号节制使用（第 01 篇全文仅剩两三处），优先拆成短句或冒号。
- 粗体只给两处用：关键结论、专有名词首次亮出处。不要整段加粗。
- 无表情符号；图片不做花纹装饰。
- 术语：插件用 `ai-proxy` 原样；「消费者」「路由」「落库」等控制台口径的词汇全系列保持一致。
- **小结（和每一节的开场句）用白话，不堆标识符。** 正文里该出现的插件名、字段名照写；到了收束段就把它们换成读者不查表也能懂的说法——`ai_log` → 「账单」、embedding/检索调用 → 「查资料那次调用」、`ActionPause` → 「请求挂在那儿不动」、上游 Body → 「请求体」。判据：把这段单独发给一个没读过前文的人，他能说清「发生了什么、我该怎么防」。用户原话（2026-10-15）：第一版小结塞满 `ai-search`/`ai-rag`/`embedding`/`Pause`，回的是「写得不够通俗易懂」。**立场那句（反直觉论点）原样保留，它是全篇唯一的加粗结论，不要为了通俗而稀释。**

## AI 味黑名单（初稿时避免，定稿时复查）

- 词汇：此外、至关重要、深入探讨、赋能、无缝、强大、织锦、宝贵、充满活力、值得注意的是、需要指出的是。
- 句式：不仅……而且……、这不仅仅是……而是……、从 X 到 Y（虚假范围）、作为/标志着/见证了。
- 结构：三段式排比、段段「首先/其次/最后」、结尾「希望这对你有帮助」。
- 定稿前可选跑一遍 `content-humanizer` skill 自查（目标 ≥40 分）；注意它的通用规则不认「我」的判断句——那是有意保留的个性，不要为凑分删掉。

## 坑的写法

- 坑只出现在咬人的那个步骤，用 blockquote callout；不单开「踩坑记录」章节。
- 普通坑给规避动作，语气口语：「别顺手改成 `true`」。
- 危险坑讲爆炸半径：「泄露的是能直接换成人民币的推理额度」，并给出正确顺序建议。
- 小结里用一句话把全部坑点名回顾。
